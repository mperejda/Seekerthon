# Solana Mobile dApp Store releases

The GitHub Actions workflow at `.github/workflows/solana-dapp-store.yml` builds,
signs, verifies, and optionally publishes the Seekerthon APK. Publishing is only
available from a manual workflow run and is gated by the `solana-dapp-store`
GitHub environment.

## One-time Publisher Portal setup

1. Create and verify the Alpine Labs publisher account at
   <https://publish.solanamobile.com>.
2. Connect the publisher wallet, fund it with enough SOL for publishing costs,
   create the Seekerthon app, and mint its App NFT.
3. Confirm the portal app uses the Android package name
   `com.alpinelabs.seekerthon`.
4. Create a Publisher Portal API key under **Settings > API Keys**.
5. Review the current Publisher Policy and Developer Agreement before enabling
   automated publishing.

The publisher wallet used for the App NFT must remain available for future app
updates.

## GitHub configuration

Create a GitHub environment named `solana-dapp-store` and add a required
reviewer. Add the Android build values as repository Actions secrets, and add
the two publisher credentials as environment secrets on `solana-dapp-store`:

| Secret | Value |
| --- | --- |
| `ANDROID_API_URL` | Production API base URL, including `/api/v1/` and the trailing slash |
| `ANDROID_KEYSTORE_BASE64` | Base64-encoded Android release keystore |
| `ANDROID_KEYSTORE_PASSWORD` | Release keystore password |
| `ANDROID_KEY_ALIAS` | Release signing key alias |
| `ANDROID_KEY_PASSWORD` | Release signing key password |
| `GOOGLE_SERVICES_JSON_BASE64` | Base64-encoded production `google-services.json` |
| `DAPP_STORE_API_KEY` (environment) | API key generated by the Solana Mobile Publisher Portal |
| `SOLANA_PUBLISHER_KEYPAIR_BASE64` (environment) | Base64-encoded Solana CLI keypair JSON for the publisher wallet |

On PowerShell, encode binary or JSON files without printing their contents:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\path\to\file")) | Set-Clipboard
```

Paste the clipboard value directly into the corresponding GitHub secret. Never
commit the keystore, Google Services file, publisher keypair, or decoded secret.

## Release process

1. Increment `versionCode` and update `versionName` in `android/app/build.gradle`.
2. Commit and push the release changes.
3. Open **Actions > Solana Mobile dApp Store > Run workflow**.
4. Enter user-facing release notes in **whats_new**.
5. Leave **publish** disabled for the first run. Download and test the signed APK
   artifact on a Seeker device.
6. Run the workflow again with **publish** enabled. Approve the protected
   environment deployment after reviewing the commit, version, and release notes.

Pushing a tag such as `android-v1.3.2` also builds and verifies a signed APK, but
tag-triggered runs never publish to the store.

Each dApp Store update must use the same Android signing key and publisher wallet
as the original release. `versionCode` must increase monotonically.
